## Method (since 2026-09-19): The Math Academy Way
The operational rules are in `CLAUDE.md`. Summary:
- **Diagnose, don't assume.** All old-course topics start `unverified`, and foundations
  are tested too.
- **Knowledge graph** (`knowledge-graph.json`): foundation topics F01–F16 sit under
  the twelve pattern topics P01–P17. Only frontier topics get taught.
- **Knowledge points**: each topic is taught in small steps, with a quiz after each
  step, then an end-of-topic quiz, then a cumulative end-of-module quiz.
- **Intuition first**: every topic has a `picture` (its geometric/visual model), and
  quizzes must test it along with why/what-breaks/counterexample/transfer questions.
- **Spaced repetition** (`tools/srs.py`, state in `progress.json`): due reviews open
  every session, interleaved, closed-book.

This replaces the old per-topic cadence (lesson → more problems → interleave after a
2–3 day gap). The old cadence was blocked practice plus a single spaced revisit.

## The lessons (rebuilt 2026-09-20; ungated 2026-09-22)
Self-contained HTML, driven by `assets/engine.js` and one content file per topic in
`content/`. Anand can learn without chat: `python3 tools/serve.py`, then
<http://localhost:8000>. 50 topics, 200 steps, 1074 questions, 111 Java practice
solutions, 264 suggested problems.

- Lesson shells in `lessons/` are generated by `tools/build.py`; edit `content/<ID>.js`, not the HTML.
- `content/problems.js` (the per-topic **suggested problems**, no solutions attached) is
  generated by `tools/build_problems.py`; the curated list lives in that script and the
  titles, difficulties and URLs are resolved from the LeetCode and CSES indexes at build
  time, so a wrong slug or task id fails the build instead of shipping a dead link.
- The old pattern lessons live in `lessons/legacy/` (0001–0036) as extra drills.
- Validate with `node tools/check_content.js`, `node tools/check_java.js` and
  `python3 tools/check_server.py`.
- `COVERAGE.md` maps the course onto CSES, the CP-31 sheet and the USACO Guide, and
  lists what is deliberately excluded (flows, suffix automata, geometry, game theory …).

### Nothing is locked (2026-09-22)
Anand's report: *"it looks like I am giving the quiz without learning about the
material."* He was right, and it was structural, not cosmetic:

- Every legacy topic is `unverified`, so `srs.py frontier` returned an empty "learn"
  list and a placement list. The dashboard's first actionable line was therefore
  *take a placement quiz* — a cold test, with no lesson offered anywhere.
- A lesson page then opened with the placement quiz and an auto-running prerequisite
  warm-up before a single word of teaching, and locked steps 2..n behind step 1.

Now: the dashboard leads with **Learn** and lists placement as optional; the frontier is
a suggested order rather than a gate (`frontier_items` returns every unmastered topic,
prerequisite-complete ones first); lesson pages show all steps expanded from the start,
with placement and warm-up folded into skippable `<details>`; a step's questions report
"not solid yet" and suggest a reread instead of stopping the lesson; the end-of-topic
quiz is always available and still folds the explanations shut for closed book.
The quizzes, mastery scoring, spaced repetition and recording are all unchanged.

## Lesson content format (for any new topic)
- One step per knowledge point: short explanation, worked example with labelled subgoals,
  the `picture` (inline SVG or ASCII), then ≥ 4 questions (3 to pass, 1 spare), mixed types.
- Question types: `mcq`, `multi`, `num`, `free` (self-graded against a rubric).
- Every topic quiz: ≥ 5 questions including a free-response and a transfer question.
- Keep MCQ options the same length, so formatting gives nothing away (the checker warns).
- Compute every numeric/trace answer with a script before writing it.
