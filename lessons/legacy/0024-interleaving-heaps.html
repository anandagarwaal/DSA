Lesson 0024 · Interleaving

Mixed Retrieval — Heaps + Trees + Lists + Stacks + Search + Windows + Pointers + Hashing

Eight tools. The new axis: "best k / streaming priority" vs full ordering vs single-pass scan.

Do this after a 2–3 day gap from Lessons 0022–0023. The skill is the trigger test: the moment you hear "k largest / smallest / closest / most frequent," "merge k," or "running median," a heap should fire — and you should say which direction and why before a line of code.

The decision fork to internalise

SignalReach for
"k largest/smallest/closest/most frequent"Size-k heap (opposite-direction)
"Merge k sorted …" / kth in sorted matrixMin-heap of frontier heads
"Running / streaming median"Two heaps (max-lo, min-hi)
"Repeatedly take the best remaining"Heap-greedy loop
Bottom-up tree property; level orderDFS postorder / BFS
Next/previous greater; nested matchingMonotonic stack
"Min/max value such that feasible"; sorted lookupBinary search
Contiguous run under a constraintSliding window
"Seen it?" / counts / group-byHash set / map

Drill — name the tool, cold

State the approach and its complexity in under 30 seconds, then check.

Debrief

The heap trap is direction: k largest wants a min-heap of size k, k smallest a max-heap. The second trap is reaching for a heap when a single pass or a bucket sort is strictly better — "top k frequent" has an O(n) bucket alternative, "kth in sorted matrix" has a binary-search-on-value alternative. Naming the heap solution and its cheaper specialised rival is the Staff-level signal.
