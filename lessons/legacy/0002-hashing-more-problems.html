Lesson 0002 · Arrays & Hashing — Reps

More Hashing Problems

Four more reps to turn the pattern from "I follow it" into "I reach for it without thinking."

You've met the three faces of hashing in Lesson 0001: membership, group-by, and prefix-sum counting. Fluency comes from reps, not new theory — so these are drills only. Same rule: fight each one before opening the hint. Aim to name the tool aloud ("set for membership", "count signature", …) before you write code — that naming reflex is exactly what the interview clock rewards.

For each problem, state the brute force and its complexity first, then the hashed improvement. Saying "naive is O(n²), the map makes it O(n)" out loud is half of what the Google interviewer is listening for.

Drill 1 — membership LeetCode 217 · Contains Duplicate

Return true if any value appears at least twice in int[] nums.

Hint

"Have I seen this before?" → HashSet. Add as you go; if add returns false, the value was already present.

Solution (Java) 
public boolean containsDuplicate(int[] nums) {
    Set<Integer> seen = new HashSet<>();
    for (int x : nums) {
        if (!seen.add(x)) return true;   // add() returns false if already present
    }
    return false;
}

Time O(n) · Space O(n). Insight: add()'s boolean return makes the membership-check and insert a single operation.

Drill 2 — count signature LeetCode 242 · Valid Anagram

Given s and t, return true if t is an anagram of s.

Hint

Two strings are anagrams iff their letter counts match. For lowercase ASCII, a length-26 int[] is a faster "map" than a HashMap: increment for s, decrement for t, then check all zero.

Solution (Java) 
public boolean isAnagram(String s, String t) {
    if (s.length() != t.length()) return false;
    int[] count = new int[26];
    for (int i = 0; i < s.length(); i++) {
        count[s.charAt(i) - 'a']++;
        count[t.charAt(i) - 'a']--;
    }
    for (int c : count) if (c != 0) return false;
    return true;
}

Time O(n) · Space O(1) (fixed 26). Insight: when the key universe is small and fixed, an array is the hash map — faster and zero boxing. For full Unicode, fall back to a HashMap<Character,Integer>.

Drill 3 — the O(n) star LeetCode 128 · Longest Consecutive Sequence

Given an unsorted int[] nums, return the length of the longest run of consecutive integers. Must be O(n) — sorting (O(n log n)) is disqualified.

Hint

Put everything in a HashSet. A number starts a sequence only if x − 1 is not in the set. From each such start, walk x+1, x+2, … counting length. Each number is visited at most twice overall, so it's O(n) despite the inner loop.

Solution (Java) 
public int longestConsecutive(int[] nums) {
    Set<Integer> set = new HashSet<>();
    for (int x : nums) set.add(x);
    int best = 0;
    for (int x : set) {
        if (set.contains(x - 1)) continue;   // not a sequence start
        int len = 1, cur = x;
        while (set.contains(cur + 1)) { cur++; len++; }
        best = Math.max(best, len);
    }
    return best;
}

Time O(n) · Space O(n). Insight: the x−1 guard is what keeps it linear — without it you'd re-walk every sequence from every member. This "only start work at a boundary" trick recurs (e.g. in matrix/island problems). A favourite at Google.

Drill 4 — map + bucket LeetCode 347 · Top K Frequent Elements

Return the k most frequent elements of int[] nums. Expected better than O(n log n).

Hint

Step 1: count frequencies in a map (hashing). Step 2: you could pop the top-k from a heap (O(n log k)) — but frequencies range only 1..n, so bucket by frequency: buckets[f] = list of values seen f times. Walk buckets high→low to collect k. That's O(n).

Solution (Java) 
public int[] topKFrequent(int[] nums, int k) {
    Map<Integer,Integer> freq = new HashMap<>();
    for (int x : nums) freq.merge(x, 1, Integer::sum);

    List<Integer>[] bucket = new List[nums.length + 1]; // index = frequency
    for (var e : freq.entrySet()) {
        int f = e.getValue();
        if (bucket[f] == null) bucket[f] = new ArrayList<>();
        bucket[f].add(e.getKey());
    }
    int[] ans = new int[k]; int idx = 0;
    for (int f = bucket.length - 1; f >= 0 && idx < k; f--) {
        if (bucket[f] == null) continue;
        for (int v : bucket[f]) { if (idx < k) ans[idx++] = v; }
    }
    return ans;
}

Time O(n) · Space O(n). Insight: hashing counts; bucket-by-value beats a heap when the key range is bounded. Mention both approaches in an interview — the heap version is the natural bridge to the upcoming Heaps / Top-K module.
