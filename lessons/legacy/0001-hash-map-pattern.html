Lesson 0001 · Arrays & Hashing

The Hash Map Pattern

Trading space for time — the single highest-frequency idea in Google & Meta coding rounds.

You're rusty, so let's start where the leverage is highest. The most common move in interview coding is this: a brute-force scan re-derives information it has already seen. A hash map remembers that information so each step becomes O(1). Master this reflex and a large fraction of "mediums" collapse into a single pass.

The Google bar isn't "did it pass" — it's "can you say why O(n) is achievable and prove it." The Meta bar is "can you write it cleanly in 10 minutes." This pattern trains both.

The core idea

Two questions a hash structure answers in ~O(1):

  • "Have I seen this before?" → HashSet (membership).
  • "What value / count / index is associated with this key?" → HashMap.

If your brute force has a nested loop where the inner loop searches for something, ask: could I have stored that something in a map on the way in? Usually yes — turning O(n²) into O(n) at the cost of O(n) memory.

Pattern signals. Reach for hashing when you see: "find a pair / complement", "count occurrences", "group by some key", "detect duplicates", "find the longest/shortest subarray with property X" (often prefix-sum + map). If the problem needs sorted order or top-K, that's a different tool — note it and move on.

Now drill — three problems

Drill 1 — warm-up LeetCode 1 · Two Sum

Given int[] nums and int target, return indices of the two numbers that add to target. Exactly one solution; can't reuse an element.

Hint

As you walk the array, for each x you need to know whether target − x appeared earlier — and at what index. Store value → index in a map as you go, so the complement check is O(1). One pass is enough.

Solution (Java) 
public int[] twoSum(int[] nums, int target) {
    Map<Integer,Integer> seen = new HashMap<>(); // value -> index
    for (int i = 0; i < nums.length; i++) {
        int need = target - nums[i];
        if (seen.containsKey(need)) {
            return new int[]{ seen.get(need), i };
        }
        seen.put(nums[i], i);
    }
    return new int[]{-1, -1}; // unreachable per constraints
}

Time O(n) · Space O(n). Insight: check the complement before inserting the current element, so you never pair an element with itself.

Drill 2 — core LeetCode 49 · Group Anagrams

Given String[] strs, group the anagrams together. Anagrams share the same multiset of letters.

Hint

You need a canonical key that's identical for all anagrams. Sorting the characters gives one ("eat"→"aet"). Map that key → list of originals using computeIfAbsent. (Faster key: a length-26 count signature.)

Solution (Java) 
public List<List<String>> groupAnagrams(String[] strs) {
    Map<String,List<String>> groups = new HashMap<>();
    for (String s : strs) {
        char[] c = s.toCharArray();
        Arrays.sort(c);
        String key = new String(c);
        groups.computeIfAbsent(key, k -> new ArrayList<>()).add(s);
    }
    return new ArrayList<>(groups.values());
}

Time O(n·k log k) for n strings of length k (sorting each key) · Space O(n·k). A count-array key drops it to O(n·k). Insight: hashing isn't just lookup — it's grouping by a derived key.

Drill 3 — stretch (Google/Meta favorite) LeetCode 560 · Subarray Sum = K

Given int[] nums and int k, count the contiguous subarrays summing to k. Numbers can be negative, so a sliding window won't work.

Hint

Let prefix[i] = sum of the first i elements. A subarray (j, i] sums to k exactly when prefix[i] − prefix[j] = k, i.e. prefix[j] = prefix[i] − k. So as you sweep, count how many earlier prefix sums equal current − k. A map of prefix-sum → how many times seen answers that in O(1).

Solution (Java) 
public int subarraySum(int[] nums, int k) {
    Map<Integer,Integer> count = new HashMap<>();
    count.put(0, 1);              // empty prefix: sum 0 seen once
    int prefix = 0, ans = 0;
    for (int x : nums) {
        prefix += x;
        ans += count.getOrDefault(prefix - k, 0);
        count.merge(prefix, 1, Integer::sum);
    }
    return ans;
}

Time O(n) · Space O(n). This is the prefix-sum + hash map template — it recurs constantly. The count.put(0,1) seed handles subarrays starting at index 0; forgetting it is the classic bug. Be ready to explain why the negative-number case rules out two pointers.

What you just trained

Three faces of one pattern: lookup (Two Sum), grouping by derived key (Group Anagrams), and prefix-sum counting (Subarray Sum). In an interview, the trigger is the same each time: "my brute force keeps re-searching — can a map remember it instead?"
