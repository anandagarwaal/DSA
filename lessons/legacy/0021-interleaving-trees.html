Lesson 0021 · Interleaving

Mixed Retrieval — Trees + Lists + Stacks + Search + Windows + Pointers + Hashing

Seven tools. The new axis: recursive structure (trees) vs linear structure (everything prior).

Do this after a 2–3 day gap from Lessons 0019–0020. The skill is picking the traversal fast — BFS vs DFS, and which DFS order — and recognising when a tree problem is really a search (BST) or a hashing problem in disguise.

The decision fork to internalise

SignalReach for
Bottom-up tree property (height, diameter, balance)DFS postorder + global
Level-by-level / min depth / right viewBFS (freeze level size)
Sorted order or search in a BSTInorder DFS / BST bounds
Node list: middle, cycle, reorderFast/slow + dummy + reversal
Next/previous greater; nested matchingStack
"Min/max value such that feasible"; sorted lookupBinary search
"Seen it?" / counts / group-byHash set / map

Drill — name the tool, cold

State the approach and its complexity in under 30 seconds, then check.

Debrief

For trees, the first fork is BFS vs DFS; the second is which DFS order. "Compute a property" is almost always postorder with a global best. "Shortest/level" is BFS. A BST adds the inorder-is-sorted and bounds tricks. If a problem says "BST," that's a hint to exploit ordering rather than scan all nodes — naming that is the Staff signal.
