Lesson 0031 · Dynamic Programming

Dynamic Programming — State, Recurrence, Memoise

DP isn't a bag of tricks. It's one procedure: name the state, write the recurrence, then memoise or tabulate.

The candidates who fear DP are trying to recognise memorised solutions. The candidates who pass derive them with a fixed procedure: define the state, list the choices, write the recurrence, set the base case, decide the fill order. Keep the DP framework reference open — this lesson drills running that procedure live.

DP applies under two conditions: optimal substructure (the optimum is built from sub-optima) and overlapping subproblems (the same subproblem recurs, so caching pays). The Staff-level skill is stating the recurrence in one sentence — "the best for n is the best of (rob this + best for n-2) or (skip + best for n-1)." Once that sentence exists, the code is mechanical.

Memoization vs tabulation

Same recurrence, two encodings. Top-down memoization: write the natural recursion, add a cache. Bottom-up tabulation: fill an array in dependency order. Derive top-down (it's safest), then mention bottom-up + the O(1) rolling-array refinement as follow-ups — interviewers love that progression.

Pattern signals. "how many ways …", "minimum / maximum cost to …", "longest / shortest subsequence …", "can you reach / partition / make …", "best profit with constraints." If a greedy choice can be locally wrong yet globally needed, and brute force re-solves the same subproblems, it's DP.

Check your model first

Drill — three problems

Drill 1 — linear DP LeetCode 198 · House Robber

Max sum of non-adjacent elements (can't rob two neighbouring houses).

Hint

State dp[i] = best loot through house i. Choice: rob i (dp[i-2]+a[i]) or skip (dp[i-1]). Only the last two values matter → O(1) space.

Solution (Java) 
public int rob(int[] a) {
    int prev2 = 0, prev1 = 0;                 // best up to i-2, i-1
    for (int x : a) {
        int cur = Math.max(prev1, prev2 + x); // skip vs rob
        prev2 = prev1; prev1 = cur;
    }
    return prev1;
}

Time O(n) · Space O(1). Insight: the recurrence dp[i]=max(dp[i-1], dp[i-2]+a[i]) depends on only two prior states, so two scalars replace the whole array — state the array version first, then collapse it.

Drill 2 — unbounded knapsack LeetCode 322 · Coin Change

Fewest coins to make a target amount; coins may be reused. Return -1 if impossible.

Hint

State dp[a] = fewest coins for amount a. For each amount, try every coin: dp[a] = min(dp[a], dp[a-coin]+1). Base dp[0]=0.

Solution (Java) 
public int coinChange(int[] coins, int amount) {
    int[] dp = new int[amount + 1];
    Arrays.fill(dp, amount + 1);              // sentinel "infinity"
    dp[0] = 0;
    for (int a = 1; a <= amount; a++)
        for (int c : coins)
            if (c <= a) dp[a] = Math.min(dp[a], dp[a - c] + 1);
    return dp[amount] > amount ? -1 : dp[amount];
}

Time O(amount·coins) · Space O(amount). Insight: this is bottom-up because every dp[a] depends on smaller amounts already computed — the natural fill order is just "amounts ascending." Coins reusable ⇒ inner loop over coins, no index restriction.

Drill 3 — two-sequence grid DP LeetCode 1143 · Longest Common Subsequence

Length of the longest subsequence common to two strings.

Hint

State dp[i][j] = LCS of a[0..i) and b[0..j). If the chars match, 1 + dp[i-1][j-1]; else max(dp[i-1][j], dp[i][j-1]).

Solution (Java) 
public int longestCommonSubsequence(String a, String b) {
    int m = a.length(), n = b.length();
    int[][] dp = new int[m + 1][n + 1];       // row/col 0 = empty prefix = 0
    for (int i = 1; i <= m; i++)
        for (int j = 1; j <= n; j++)
            dp[i][j] = (a.charAt(i-1) == b.charAt(j-1))
                ? dp[i-1][j-1] + 1
                : Math.max(dp[i-1][j], dp[i][j-1]);
    return dp[m][n];
}

Time O(m·n) · Space O(m·n) (reducible to O(n) with two rows). Insight: the match-vs-mismatch branch is the entire recurrence; nearly every two-string DP (edit distance, shortest common supersequence) is a variation on this grid.
