Lesson 0028 · Graphs

Graphs — Traversal, Topological Sort & Union-Find

Most graph questions are BFS, DFS, topo sort, or union-find in disguise. The hard part is seeing the graph.

A graph is just nodes plus edges; the work is recognising one. Grids, course prerequisites, friend networks, word ladders, equation chains — all graphs. Once you build the adjacency list, four tools cover the vast majority of problems: BFS (shortest path in unweighted graphs), DFS (connectivity, cycles, components), topological sort (ordering under dependencies), and union-find (dynamic connectivity / grouping).

The Staff-level move is modelling: stating "nodes are X, an edge means Y, so this is a shortest-path / cycle-detection / ordering problem." Most candidates can run BFS; fewer can look at "minimum steps to transform word A into word B" and immediately say "unweighted shortest path → BFS." The reduction is the differentiator. Always track visited — a graph, unlike a tree, has cycles.

The two traversal skeletons

// BFS — shortest path in an UNWEIGHTED graph, level by level.
Queue<Integer> q = new LinkedList<>(); q.offer(src);
boolean[] seen = new boolean[n]; seen[src] = true;
int steps = 0;
while (!q.isEmpty()) {
    int sz = q.size();                       // freeze the level
    for (int i = 0; i < sz; i++) {
        int u = q.poll();
        for (int v : adj.get(u))
            if (!seen[v]) { seen[v] = true; q.offer(v); }
    }
    steps++;
}

// DFS — connectivity, components, cycle detection.
void dfs(int u, boolean[] seen, List<List<Integer>> adj) {
    seen[u] = true;
    for (int v : adj.get(u)) if (!seen[v]) dfs(v, seen, adj);
}
Pattern signals. "shortest / fewest steps" (unweighted → BFS), "number of islands / connected components / provinces" (DFS or union-find), "course schedule / build order / can finish" (topo sort + cycle check), "are these in the same group / accounts merge" (union-find), "clone / copy a graph" (DFS/BFS + hash map of old→new). Drill — three problems

Drill 1 — grid as graph LeetCode 200 · Number of Islands

Count connected groups of land ('1') in a grid.

Hint

Each cell is a node; edges join 4-adjacent land cells. Scan the grid; on each unvisited '1', DFS/BFS to sink its whole island, incrementing a counter once per launch.

Solution (Java) 
public int numIslands(char[][] grid) {
    int count = 0;
    for (int r = 0; r < grid.length; r++)
        for (int c = 0; c < grid[0].length; c++)
            if (grid[r][c] == '1') { sink(grid, r, c); count++; }
    return count;
}
private void sink(char[][] g, int r, int c) {
    if (r < 0 || c < 0 || r >= g.length || c >= g[0].length || g[r][c] != '1') return;
    g[r][c] = '0';                            // mark visited in place
    sink(g, r+1, c); sink(g, r-1, c); sink(g, r, c+1); sink(g, r, c-1);
}

Time O(m·n) · Space O(m·n) recursion. Insight: "connected components on a grid" is the most common disguised graph — each DFS launch flattens exactly one component.

Drill 2 — topological sort LeetCode 207 · Course Schedule

Given prerequisite pairs, decide whether all courses can be finished (no cycle).

Hint

Build a graph edge prereq→course and an in-degree array. Kahn's BFS: queue all in-degree-0 nodes, pop and decrement neighbours, enqueue new zeros. If you process all n nodes, no cycle.

Solution (Java) 
public boolean canFinish(int n, int[][] prereqs) {
    List<List<Integer>> adj = new ArrayList<>();
    for (int i = 0; i < n; i++) adj.add(new ArrayList<>());
    int[] indeg = new int[n];
    for (int[] p : prereqs) { adj.get(p[1]).add(p[0]); indeg[p[0]]++; }
    Queue<Integer> q = new LinkedList<>();
    for (int i = 0; i < n; i++) if (indeg[i] == 0) q.offer(i);
    int done = 0;
    while (!q.isEmpty()) {
        int u = q.poll(); done++;
        for (int v : adj.get(u)) if (--indeg[v] == 0) q.offer(v);
    }
    return done == n;                          // all placed ⇒ acyclic
}

Time O(V+E) · Space O(V+E). Insight: a leftover node with non-zero in-degree is a cycle — Kahn's algorithm detects the cycle and produces the order in one pass.

Drill 3 — union-find LeetCode 547 · Number of Provinces

Given an adjacency matrix of city connections, count the connected provinces.

Hint

Union-find: start with n singletons, union each connected pair, then count distinct roots. Use path compression + union by rank for near-O(1) operations.

Solution (Java) 
public int findCircleNum(int[][] M) {
    int n = M.length, count = n;
    int[] parent = new int[n];
    for (int i = 0; i < n; i++) parent[i] = i;
    for (int i = 0; i < n; i++)
        for (int j = i + 1; j < n; j++)
            if (M[i][j] == 1 && union(parent, i, j)) count--;  // merged two → one fewer
    return count;
}
private int find(int[] p, int x) {
    while (p[x] != x) { p[x] = p[p[x]]; x = p[x]; }   // path compression
    return x;
}
private boolean union(int[] p, int a, int b) {
    int ra = find(p, a), rb = find(p, b);
    if (ra == rb) return false;
    p[ra] = rb; return true;
}

Time ~O(n²·α) · Space O(n). Insight: union-find shines when connectivity is dynamic (edges arrive over time) or you only need group membership, not paths — that's when it beats a fresh DFS each query.
