Lesson 0023 · Heaps — Reps

More Heap Problems

Four reps: k-closest, a greedy scheduler, k-th in a sorted matrix, and a kth-largest stream class.

From Lesson 0022 you have the size-k heap, multi-list merge, and two-heaps. These reps stretch into geometry, greedy simulation, and a sorted-matrix search. Decide min- vs max-heap and the comparator out loud before coding.

Drill 1 — k closest by distance LeetCode 973 · K Closest Points to Origin

Return the k points nearest the origin.

Hint

k closest = k smallest distances → max-heap of size k keyed on squared distance (no sqrt needed). Evict the farthest when it overflows.

Solution (Java) 
public int[][] kClosest(int[][] points, int k) {
    PriorityQueue<int[]> max =
        new PriorityQueue<>((a, b) -> dist(b) - dist(a));   // max-heap by distance
    for (int[] p : points) {
        max.offer(p);
        if (max.size() > k) max.poll();                    // drop the farthest
    }
    return max.toArray(new int[0][]);
}
private int dist(int[] p) { return p[0]*p[0] + p[1]*p[1]; }

Time O(n log k) · Space O(k). Insight: comparing squared distances avoids floating point entirely — a small correctness/precision win worth stating.

Drill 2 — greedy with a heap LeetCode 1046 · Last Stone Weight

Repeatedly smash the two heaviest stones; return the last remaining weight (or 0).

Hint

Max-heap. Poll the two largest, push back their difference if non-zero, repeat until ≤ 1 stone remains.

Solution (Java) 
public int lastStoneWeight(int[] stones) {
    PriorityQueue<Integer> max = new PriorityQueue<>(Collections.reverseOrder());
    for (int s : stones) max.offer(s);
    while (max.size() > 1) {
        int a = max.poll(), b = max.poll();
        if (a != b) max.offer(a - b);
    }
    return max.isEmpty() ? 0 : max.peek();
}

Time O(n log n) · Space O(n). Insight: "repeatedly take the best remaining" is the canonical heap-greedy loop — recognising that phrasing is the trigger to reach for a PQ.

Drill 3 — kth in sorted matrix LeetCode 378 · Kth Smallest in a Sorted Matrix

Rows and columns each sorted ascending; find the k-th smallest value.

Hint

Min-heap seeded with the first element of each row (or just row 0). Pop k times; when you pop (r,c), push (r,c+1). (A binary-search-on-value approach is even better — note it.)

Solution (Java) 
public int kthSmallest(int[][] matrix, int k) {
    int n = matrix.length;
    PriorityQueue<int[]> pq =
        new PriorityQueue<>((a, b) -> matrix[a[0]][a[1]] - matrix[b[0]][b[1]]);
    for (int r = 0; r < Math.min(n, k); r++) pq.offer(new int[]{r, 0});
    int val = 0;
    for (int i = 0; i < k; i++) {
        int[] cur = pq.poll();
        val = matrix[cur[0]][cur[1]];
        if (cur[1] + 1 < n) pq.offer(new int[]{cur[0], cur[1] + 1});
    }
    return val;
}

Time O(k log n) · Space O(n). Insight: this generalises Merge-k-Lists — each row is a sorted list. Mentioning the O(n log(range)) binary-search-on-answer alternative shows depth.

Drill 4 — design a stream class LeetCode 703 · Kth Largest Element in a Stream

Design a class that, after each add, returns the k-th largest seen so far.

Hint

Maintain a size-k min-heap. The root is always the k-th largest. On add, offer and trim to size k; return the root.

Solution (Java) 
class KthLargest {
    private final PriorityQueue<Integer> heap = new PriorityQueue<>();
    private final int k;
    public KthLargest(int k, int[] nums) {
        this.k = k;
        for (int x : nums) add(x);
    }
    public int add(int val) {
        heap.offer(val);
        if (heap.size() > k) heap.poll();
        return heap.peek();      // root of size-k min-heap = kth largest
    }
}

Time O(log k) per add · Space O(k). Insight: the size-k min-heap is the data structure — its root answers the query in O(1) with no recomputation. The template from 0022, productised.
