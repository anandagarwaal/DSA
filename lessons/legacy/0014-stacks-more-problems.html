Lesson 0014 · Stacks — Reps

More Stack Problems

Four reps: stack-with-aux-state, expression evaluation, a circular monotonic stack, and a two-stack design.

From Lesson 0013 you have plain LIFO and the monotonic stack. These reps add an auxiliary stack, parsing, the circular-array twist, and a design problem. State the stack's invariant before coding — what each element means while it sits there.

Drill 1 — stack carrying extra state LeetCode 155 · Min Stack

Design a stack with push/pop/top and getMin, all O(1).

Hint

Store pairs (value, minSoFar), or keep a parallel min-stack. Each entry records the minimum of everything at or below it.

Solution (Java) 
class MinStack {
    private final Deque<int[]> st = new ArrayDeque<>();   // {value, minSoFar}
    public void push(int x) {
        int min = st.isEmpty() ? x : Math.min(x, st.peek()[1]);
        st.push(new int[]{x, min});
    }
    public void pop()    { st.pop(); }
    public int  top()    { return st.peek()[0]; }
    public int  getMin() { return st.peek()[1]; }
}

Time O(1) all ops · Space O(n). Insight: caching the running min per entry means pop never has to recompute it — the classic "carry the answer with the element" trick.

Drill 2 — parse & evaluate LeetCode 150 · Evaluate Reverse Polish Notation

Evaluate an arithmetic expression given in Reverse Polish (postfix) notation.

Hint

Push numbers. On an operator, pop the top two operands, apply, push the result. Mind operand order for − and / (first popped is the right operand).

Solution (Java) 
public int evalRPN(String[] tokens) {
    Deque<Integer> st = new ArrayDeque<>();
    for (String tk : tokens) {
        switch (tk) {
            case "+": st.push(st.pop() + st.pop()); break;
            case "*": st.push(st.pop() * st.pop()); break;
            case "-": { int b = st.pop(), a = st.pop(); st.push(a - b); break; }
            case "/": { int b = st.pop(), a = st.pop(); st.push(a / b); break; }
            default:  st.push(Integer.parseInt(tk));
        }
    }
    return st.pop();
}

Time O(n) · Space O(n). Insight: postfix needs no precedence handling — the stack is the parse tree. Order matters only for non-commutative ops.

Drill 3 — circular monotonic LeetCode 503 · Next Greater Element II

Like next-greater, but the array is circular (wraps around).

Hint

Iterate 2n times, indexing with i % n; only push during the first pass (or push always but guard). The second lap lets earlier elements find a greater one that wraps past the end.

Solution (Java) 
public int[] nextGreaterElements(int[] a) {
    int n = a.length;
    int[] res = new int[n];
    Arrays.fill(res, -1);
    Deque<Integer> st = new ArrayDeque<>();   // indices, values decreasing
    for (int i = 0; i < 2 * n; i++) {
        int v = a[i % n];
        while (!st.isEmpty() && v > a[st.peek()]) res[st.pop()] = v;
        if (i < n) st.push(i);
    }
    return res;
}

Time O(n) · Space O(n). Insight: "simulate a second loop with i % n" is the standard circular-array trick — reuse it for circular sums and rotations too.

Drill 4 — design with two stacks LeetCode 232 · Implement Queue using Stacks

Implement FIFO queue operations using only two LIFO stacks; amortised O(1) per op.

Hint

in stack takes pushes; out stack serves pops. When out is empty, pour all of in into it — that reverses the order once.

Solution (Java) 
class MyQueue {
    private final Deque<Integer> in = new ArrayDeque<>(), out = new ArrayDeque<>();
    public void push(int x) { in.push(x); }
    public int pop()  { shift(); return out.pop(); }
    public int peek() { shift(); return out.peek(); }
    public boolean empty() { return in.isEmpty() && out.isEmpty(); }
    private void shift() {
        if (out.isEmpty()) while (!in.isEmpty()) out.push(in.pop());
    }
}

Time O(1) amortised · Space O(n). Insight: each element is moved between stacks at most once, so despite the occasional O(n) pour, the amortised cost is O(1) — same accounting argument as the monotonic stack.
