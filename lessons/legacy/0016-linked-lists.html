Lesson 0016 · Linked Lists

Linked Lists — Pointers, Reversal, Cycles

No indexing, no slicing — just pointer surgery. Three idioms cover almost every interview list problem.

Linked-list problems test careful pointer manipulation under O(1) space. Three idioms do the heavy lifting: the dummy head (uniform handling of the first node), in-place reversal (three-pointer rewire), and fast/slow pointers (find middle, detect cycles, find k-from-end). Master these and most "hards" become routine.

The dummy-head node is the unsung hero: by pointing a sentinel at the head, you never special-case "what if we delete/insert at the front?" Returning dummy.next at the end gives the possibly-new head for free. Use it whenever the head might change.

The three idioms

class ListNode { int val; ListNode next; }

// 1. In-place reversal
ListNode prev = null, cur = head;
while (cur != null) {
    ListNode nxt = cur.next;   // save
    cur.next = prev;           // rewire
    prev = cur; cur = nxt;     // advance
}
return prev;                   // new head

// 2. Fast/slow — find middle (slow lands on middle)
ListNode slow = head, fast = head;
while (fast != null && fast.next != null) { slow = slow.next; fast = fast.next.next; }

// 3. Dummy head — for any insert/delete that may touch the front
ListNode dummy = new ListNode(0); dummy.next = head;
// ...operate via a 'prev' starting at dummy...
return dummy.next;
Pattern signals. "reverse the list / sublist", "find the middle", "detect/locate a cycle", "nth node from the end", "merge two sorted lists", "remove nodes". O(1) space expected → think pointers, not a copy into an array.

Check your model first

Drill — three problems

Drill 1 — reversal LeetCode 206 · Reverse Linked List

Reverse a singly linked list and return the new head.

Hint

Three pointers: prev, cur, and a saved next. Rewire cur.next = prev each step; prev ends as the new head.

Solution (Java) 
public ListNode reverseList(ListNode head) {
    ListNode prev = null, cur = head;
    while (cur != null) {
        ListNode nxt = cur.next;
        cur.next = prev;
        prev = cur;
        cur = nxt;
    }
    return prev;
}

Time O(n) · Space O(1). Insight: always save cur.next before rewiring — overwrite it first and you lose the rest of the list. This is the #1 list bug.

Drill 2 — cycle detection LeetCode 142 · Linked List Cycle II

Detect whether the list has a cycle, and return the node where it begins (or null).

Hint

Floyd's algorithm: fast moves 2×, slow 1×; if they meet, a cycle exists. Then reset one pointer to head and advance both by 1 — they meet at the cycle's entrance.

Solution (Java) 
public ListNode detectCycle(ListNode head) {
    ListNode slow = head, fast = head;
    while (fast != null && fast.next != null) {
        slow = slow.next; fast = fast.next.next;
        if (slow == fast) {                    // cycle confirmed
            ListNode p = head;
            while (p != slow) { p = p.next; slow = slow.next; }
            return p;                          // entrance
        }
    }
    return null;
}

Time O(n) · Space O(1). Insight: the reset-to-head step works because the distance head→entrance equals meeting-point→entrance (mod cycle length). Being able to justify that is the Staff signal — most candidates just memorise it.

Drill 3 — dummy head + two pass logic LeetCode 19 · Remove Nth Node From End

Remove the n-th node from the end of the list in one pass; return the head.

Hint

Dummy head. Advance fast by n+1 steps, then move fast and slow together until fast is null; slow now sits just before the target. The dummy handles "remove the head."

Solution (Java) 
public ListNode removeNthFromEnd(ListNode head, int n) {
    ListNode dummy = new ListNode(0);
    dummy.next = head;
    ListNode fast = dummy, slow = dummy;
    for (int i = 0; i <= n; i++) fast = fast.next;   // gap of n+1
    while (fast != null) { fast = fast.next; slow = slow.next; }
    slow.next = slow.next.next;                       // unlink
    return dummy.next;
}

Time O(n) · Space O(1). Insight: the fixed n+1 gap leaves slow on the predecessor; without the dummy, removing the actual head needs a special case. The dummy erases it.
