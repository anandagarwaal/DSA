Lesson 0004 · Two Pointers

The Two-Pointers Pattern

Two indices, one array, O(1) extra space — the tool that beats hashing when the input is sorted or you must work in place.

In Lesson 0003 you spotted it: a pair-sum on a sorted array doesn't need a hash map. Two pointers walking from the ends solve it in O(n) time and O(1) space. That space win — and the ability to mutate in place — is why this pattern is everywhere in Google/Meta rounds.

The Staff-level move isn't just knowing two pointers — it's articulating the tradeoff: "hashing is O(n) space; since this is sorted, two pointers gives the same answer in O(1)." Stating that unprompted is what separates a hire from a strong-hire.

The two families

1 · Converging (opposite ends)

Start lo = 0, hi = n−1. Compare, then move the pointer that can improve the answer. Works on sorted arrays and on symmetric scans (palindromes). The comparison decides the move — that's the whole trick.

int lo = 0, hi = n - 1;
while (lo < hi) {
    if (condition met)      return ...;
    else if (sum too small) lo++;   // need a bigger value
    else                    hi--;   // need a smaller value
}

2 · Fast / slow (same direction)

Two pointers moving the same way at different speeds, or one lagging to mark a write position. Powers in-place work: dedup a sorted array, partition, remove elements, and (with a 2× fast pointer) cycle detection in linked lists — a later module.

int slow = 0;                      // write position
for (int fast = 0; fast < n; fast++) {
    if (keep(nums[fast])) nums[slow++] = nums[fast];
}
// slow = length of the kept prefix
Pattern signals. Reach for two pointers when you see: "sorted array", "pair / triplet summing to X", "palindrome", "remove / dedup in place", "O(1) extra space required", or "merge two sorted sequences". If the array is unsorted and sorting would destroy needed information (e.g. original indices), fall back to hashing.

Check your model first

Drill — four problems

Drill 1 — converging LeetCode 167 · Two Sum II (sorted)

Sorted int[] numbers; return the 1-indexed positions of the two values summing to target. Must use O(1) extra space.

Hint

If numbers[lo] + numbers[hi] is too small, only increasing lo can help; if too big, decrease hi. The sort guarantees this is safe.

Solution (Java) 
public int[] twoSum(int[] numbers, int target) {
    int lo = 0, hi = numbers.length - 1;
    while (lo < hi) {
        int sum = numbers[lo] + numbers[hi];
        if (sum == target) return new int[]{lo + 1, hi + 1};
        if (sum < target)  lo++;
        else               hi--;
    }
    return new int[]{-1, -1};
}

Time O(n) · Space O(1). Contrast with hashing Two Sum (Lesson 0001): same problem, but sorted input trades the O(n) map for O(1) pointers. Know both and when to use each.

Drill 2 — symmetric scan LeetCode 125 · Valid Palindrome

Return true if s reads the same forwards and backwards, considering only alphanumerics and ignoring case.

Hint

Pointers from both ends moving inward; skip non-alphanumerics; compare lowercased characters. Mismatch → not a palindrome.

Solution (Java) 
public boolean isPalindrome(String s) {
    int lo = 0, hi = s.length() - 1;
    while (lo < hi) {
        while (lo < hi && !Character.isLetterOrDigit(s.charAt(lo))) lo++;
        while (lo < hi && !Character.isLetterOrDigit(s.charAt(hi))) hi--;
        if (Character.toLowerCase(s.charAt(lo)) != Character.toLowerCase(s.charAt(hi)))
            return false;
        lo++; hi--;
    }
    return true;
}

Time O(n) · Space O(1). Insight: the inner skip-loops must also guard lo < hi, or an all-symbol string walks off the end.

Drill 3 — the classic LeetCode 15 · 3Sum

Return all unique triplets in int[] nums that sum to zero.

Hint

Sort first. Fix index i, then run a converging two-pointer scan on the rest for −nums[i]. Skip duplicate values for both the fixed element and the moving pointers, or you'll emit repeats. This sort + fix one + two pointers template is a top-tier Meta/Google question.

Solution (Java) 
public List<List<Integer>> threeSum(int[] nums) {
    Arrays.sort(nums);
    List<List<Integer>> res = new ArrayList<>();
    for (int i = 0; i < nums.length - 2; i++) {
        if (i > 0 && nums[i] == nums[i - 1]) continue;        // skip dup pivot
        int lo = i + 1, hi = nums.length - 1;
        while (lo < hi) {
            int sum = nums[i] + nums[lo] + nums[hi];
            if (sum == 0) {
                res.add(Arrays.asList(nums[i], nums[lo], nums[hi]));
                while (lo < hi && nums[lo] == nums[lo + 1]) lo++;  // skip dups
                while (lo < hi && nums[hi] == nums[hi - 1]) hi--;
                lo++; hi--;
            } else if (sum < 0) lo++;
            else hi--;
        }
    }
    return res;
}

Time O(n²) · Space O(1) beyond output. Insight: sorting (O(n log n)) is dominated by the O(n²) scan, and it's what enables both the two-pointer move and clean dedup.

Drill 4 — greedy converging LeetCode 11 · Container With Most Water

Heights int[] h; pick two lines forming the container holding the most water: maximise (hi − lo) · min(h[lo], h[hi]).

Hint

Start at the widest pair. Area is capped by the shorter line, so moving the taller pointer can never help — always move the shorter one inward. Greedy, and provably safe.

Solution (Java) 
public int maxArea(int[] h) {
    int lo = 0, hi = h.length - 1, best = 0;
    while (lo < hi) {
        best = Math.max(best, (hi - lo) * Math.min(h[lo], h[hi]));
        if (h[lo] < h[hi]) lo++;
        else hi--;
    }
    return best;
}

Time O(n) · Space O(1). Insight: be ready to argue why discarding the shorter line is safe — that correctness justification is the Google bar in miniature.

Interleave it back in

You now hold two pair-sum tools. Quick recall: unsorted, need original indices? → hashing (Lesson 0001). Sorted, want O(1) space? → two pointers. That fork is a textbook interview decision — rehearse saying it aloud.
