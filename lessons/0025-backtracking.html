Lesson 0025 · Backtracking

Backtracking — Choose / Explore / Un-choose

One recursion skeleton generates every subset, permutation, and combination. Vary only the choices and the prune.

Backtracking is depth-first search over a tree of partial solutions. At each node you choose an option, explore deeper, then un-choose (undo the choice) so the next branch starts clean. That undo is the whole trick — it's why the same path list can be reused across the entire search instead of copied.

The Staff-level insight is the state-space tree: every problem here is "enumerate paths in a tree where each level fixes one decision." Subsets branch include/exclude; permutations branch on which unused element comes next; combinations branch on a start index to kill duplicates. Once you see the tree, the code is mechanical — and so is the complexity (count the leaves).

The skeleton

void backtrack(State path, Choices remaining) {
    if (isComplete(path)) { results.add(copyOf(path)); return; }
    for (Choice c : remaining) {
        if (!valid(c, path)) continue;   // prune dead branches early
        path.add(c);                     // choose
        backtrack(path, narrow(remaining, c));  // explore
        path.remove(path.size() - 1);    // un-choose (the backtrack)
    }
}

You copy the path only when recording a complete solution — during the search a single mutable list is threaded through, added to and rolled back.

Pattern signals. "all subsets / combinations / permutations", "generate every valid …", "partition into …", "place N queens / fill the board", "does any arrangement satisfy …". Output is usually exponential — if the ask is to enumerate rather than count or optimise, it's backtracking (count/optimise often becomes DP, next module).

Check your model first

Drill — three problems

Drill 1 — include/exclude tree LeetCode 78 · Subsets

Return all subsets of a distinct-integer array (the power set).

Hint

Recurse with a start index. Record the current path at every node (every node is a valid subset), then branch on each later element.

Solution (Java) 
public List<List<Integer>> subsets(int[] nums) {
    List<List<Integer>> res = new ArrayList<>();
    backtrack(nums, 0, new ArrayList<>(), res);
    return res;
}
private void backtrack(int[] nums, int start, List<Integer> path,
                       List<List<Integer>> res) {
    res.add(new ArrayList<>(path));          // record a copy at every node
    for (int i = start; i < nums.length; i++) {
        path.add(nums[i]);                   // choose
        backtrack(nums, i + 1, path, res);   // explore (i+1 avoids reuse/dupes)
        path.remove(path.size() - 1);        // un-choose
    }
}

Time O(n·2ⁿ) · Space O(n) recursion. Insight: the start index is what makes each subset appear once — it forbids ever looking backward, killing permuted duplicates.

Drill 2 — permutations with a used set LeetCode 46 · Permutations

Return all orderings of a distinct-integer array.

Hint

No start index here — order matters, so any unused element can come next. Track which indices are used with a boolean array; record when the path length hits n.

Solution (Java) 
public List<List<Integer>> permute(int[] nums) {
    List<List<Integer>> res = new ArrayList<>();
    backtrack(nums, new boolean[nums.length], new ArrayList<>(), res);
    return res;
}
private void backtrack(int[] nums, boolean[] used, List<Integer> path,
                       List<List<Integer>> res) {
    if (path.size() == nums.length) { res.add(new ArrayList<>(path)); return; }
    for (int i = 0; i < nums.length; i++) {
        if (used[i]) continue;               // skip already-placed elements
        used[i] = true; path.add(nums[i]);   // choose
        backtrack(nums, used, path, res);    // explore
        path.remove(path.size() - 1); used[i] = false;  // un-choose (both!)
    }
}

Time O(n·n!) · Space O(n). Insight: permutations scan from 0 with a used[] guard (any unused next); subsets/combinations scan from start. That single difference is the whole subset-vs-permutation fork.

Drill 3 — prune on a grid LeetCode 79 · Word Search

Decide whether a word can be formed by adjacent cells in a grid (no cell reused).

Hint

DFS from each cell. Mark the current cell visited (e.g. overwrite with a sentinel), explore the four neighbours for the next letter, then restore it on the way out — that restore is the backtrack.

Solution (Java) 
public boolean exist(char[][] board, String word) {
    for (int r = 0; r < board.length; r++)
        for (int c = 0; c < board[0].length; c++)
            if (dfs(board, word, 0, r, c)) return true;
    return false;
}
private boolean dfs(char[][] b, String w, int k, int r, int c) {
    if (k == w.length()) return true;
    if (r < 0 || c < 0 || r >= b.length || c >= b[0].length
            || b[r][c] != w.charAt(k)) return false;
    char tmp = b[r][c]; b[r][c] = '#';       // choose: mark visited
    boolean found = dfs(b, w, k+1, r+1, c) || dfs(b, w, k+1, r-1, c)
                 || dfs(b, w, k+1, r, c+1) || dfs(b, w, k+1, r, c-1);
    b[r][c] = tmp;                            // un-choose: restore
    return found;
}

Time O(m·n·4ᴸ) for word length L · Space O(L). Insight: the in-place mark-and-restore avoids a separate visited set, and the early character-mismatch return is the prune that keeps it tractable.
