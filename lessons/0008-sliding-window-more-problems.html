Lesson 0008 · Sliding Window — Reps

More Sliding Window Problems

Four reps building to Minimum Window Substring — the canonical "need-counts" window and a Google/Meta staple.

From Lesson 0007 you have the fixed and variable shapes. These reps add the count-matching window: instead of a single sum, the validity test is "does the window contain enough of each required character?" State the window's invariant aloud before coding — it's the part interviewers probe.

Drill 1 — fixed window of counts LeetCode 567 · Permutation in String

Does s2 contain any permutation of s1 as a substring?

Hint

A permutation = same character counts. Slide a window of length s1.length() over s2; track how many of the 26 counts currently match the target. When all 26 match, you found one.

Solution (Java) 
public boolean checkInclusion(String s1, String s2) {
    if (s1.length() > s2.length()) return false;
    int[] need = new int[26], win = new int[26];
    for (char c : s1.toCharArray()) need[c - 'a']++;
    int k = s1.length();
    for (int r = 0; r < s2.length(); r++) {
        win[s2.charAt(r) - 'a']++;
        if (r >= k) win[s2.charAt(r - k) - 'a']--;   // evict left edge
        if (Arrays.equals(need, win)) return true;
    }
    return false;
}

Time O(n) · Space O(1) (26 fixed). Insight: comparing two length-26 arrays is O(26)=O(1); the window stays exactly k wide so eviction is mechanical.

Drill 2 — at-most-K window LeetCode 424 · Longest Repeating Character Replacement

You may replace up to k characters. Find the longest substring of a single repeated letter achievable.

Hint

A window is valid when (windowLen − maxFreqInWindow) ≤ k — the non-majority chars are the ones you'd replace. Grow right; if invalid, slide left by one. Track maxFreq as the running peak (it need not shrink for correctness).

Solution (Java) 
public int characterReplacement(String s, int k) {
    int[] count = new int[26];
    int left = 0, maxFreq = 0, best = 0;
    for (int right = 0; right < s.length(); right++) {
        maxFreq = Math.max(maxFreq, ++count[s.charAt(right) - 'a']);
        if (right - left + 1 - maxFreq > k) {   // too many to replace
            count[s.charAt(left) - 'a']--;
            left++;
        }
        best = Math.max(best, right - left + 1);
    }
    return best;
}

Time O(n) · Space O(1). Insight: the window never shrinks below its best, so a stale maxFreq is harmless — a subtle but interview-worthy correctness argument.

Drill 3 — at-most-K distinct LeetCode 904 · Fruit Into Baskets

Two baskets, each one fruit type. Find the longest contiguous run containing at most 2 distinct values.

Hint

This is "longest subarray with at most 2 distinct" generalised. Keep a count map; while map.size() > 2, shrink from the left, removing the key when its count hits 0.

Solution (Java) 
public int totalFruit(int[] fruits) {
    Map<Integer,Integer> count = new HashMap<>();
    int left = 0, best = 0;
    for (int right = 0; right < fruits.length; right++) {
        count.merge(fruits[right], 1, Integer::sum);
        while (count.size() > 2) {
            int f = fruits[left++];
            if (count.merge(f, -1, Integer::sum) == 0) count.remove(f);
        }
        best = Math.max(best, right - left + 1);
    }
    return best;
}

Time O(n) · Space O(1) (≤3 keys). Insight: merge with removal-at-zero is the clean idiom for "count map as a multiset" — reuse it everywhere.

Drill 4 — the "hard" count window LeetCode 76 · Minimum Window Substring

Find the smallest substring of s containing all characters of t (with multiplicity). A classic hard.

Hint

Track need counts and a missing counter (total chars still required). Grow right, decrementing missing when a needed char arrives. When missing==0, shrink left as far as still-valid, recording the smallest window.

Solution (Java) 
public String minWindow(String s, String t) {
    int[] need = new int[128];
    for (char c : t.toCharArray()) need[c]++;
    int missing = t.length(), left = 0, bestLen = Integer.MAX_VALUE, bestL = 0;
    for (int right = 0; right < s.length(); right++) {
        if (need[s.charAt(right)]-- > 0) missing--;     // consumed a needed char
        while (missing == 0) {                          // valid → try to shrink
            if (right - left + 1 < bestLen) { bestLen = right - left + 1; bestL = left; }
            if (need[s.charAt(left)]++ == 0) missing++;  // about to drop a needed char
            left++;
        }
    }
    return bestLen == Integer.MAX_VALUE ? "" : s.substring(bestL, bestL + bestLen);
}

Time O(n) · Space O(1) (128 fixed). Insight: the array goes negative for surplus chars, so the > 0 / == 0 guards fire only on needed ones — that's the trick that keeps it one pass.
