Lesson 0035 · Intervals & Greedy — Reps

More Intervals & Greedy Problems

Four reps: insert-and-merge, minimum arrows, the jump game, and gas station — three classic greedy proofs.

From Lesson 0034 you have sort-and-sweep and the exchange argument. These reps cover interval insertion, an overlap-counting greedy, and two pure-greedy classics where the proof that the local choice is safe is the whole interview point. Articulate the justification, not just the loop.

Drill 1 — insert into sorted intervals LeetCode 57 · Insert Interval

Insert a new interval into a sorted, non-overlapping list and merge as needed.

Hint

Three phases: copy intervals strictly before the new one, merge all that overlap it into one, then copy the rest. No full re-sort needed — the input is already sorted.

Solution (Java) 
public int[][] insert(int[][] intervals, int[] nw) {
    List<int[]> out = new ArrayList<>();
    int i = 0, n = intervals.length;
    while (i < n && intervals[i][1] < nw[0]) out.add(intervals[i++]);   // before
    while (i < n && intervals[i][0] <= nw[1]) {                         // overlapping
        nw[0] = Math.min(nw[0], intervals[i][0]);
        nw[1] = Math.max(nw[1], intervals[i][1]);
        i++;
    }
    out.add(nw);
    while (i < n) out.add(intervals[i++]);                             // after
    return out.toArray(new int[0][]);
}

Time O(n) · Space O(n). Insight: because the list is pre-sorted, the three-phase walk avoids an O(n log n) re-sort — recognising the input is already ordered is the optimisation.

Drill 2 — overlap-counting greedy LeetCode 452 · Minimum Arrows to Burst Balloons

Fewest arrows to burst all balloons, where each arrow clears every balloon spanning its x.

Hint

Sort by end. Shoot an arrow at the first balloon's end; it bursts every balloon starting at or before that x. Skip them, then shoot again at the next uncovered balloon's end.

Solution (Java) 
public int findMinArrowShots(int[][] points) {
    Arrays.sort(points, (a, b) -> Integer.compare(a[1], b[1]));  // by END (avoid overflow)
    int arrows = 1, end = points[0][1];
    for (int[] p : points) {
        if (p[0] > end) {            // this balloon starts after the last arrow's x
            arrows++; end = p[1];    // need a fresh arrow at its end
        }
    }
    return arrows;
}

Time O(n log n) · Space O(1). Insight: same earliest-end greedy as non-overlapping intervals — shooting at the earliest end maximises balloons burst per arrow. Use Integer.compare to dodge subtraction overflow on extreme coordinates.

Drill 3 — reachability greedy LeetCode 55 · Jump Game

Each value is the max jump from that index; can you reach the last index?

Hint

Track the farthest index reachable so far. Sweep left to right; if you ever stand beyond that reach, you're stuck. Otherwise extend reach by i + nums[i].

Solution (Java) 
public boolean canJump(int[] nums) {
    int reach = 0;
    for (int i = 0; i < nums.length; i++) {
        if (i > reach) return false;             // unreachable gap
        reach = Math.max(reach, i + nums[i]);    // extend the frontier
    }
    return true;
}

Time O(n) · Space O(1). Insight: the greedy "track farthest reach" beats the obvious O(n²) DP — the safe local choice is simply always extending the frontier, since any reachable index keeps every earlier reachable index reachable.

Drill 4 — circuit greedy LeetCode 134 · Gas Station

Find the start index to complete the circuit, or -1 if impossible.

Hint

If total gas ≥ total cost, a solution exists. Sweep tracking a running tank; whenever it goes negative, no start in [start..i] works, so reset start to i+1 and zero the tank.

Solution (Java) 
public int canCompleteCircuit(int[] gas, int[] cost) {
    int total = 0, tank = 0, start = 0;
    for (int i = 0; i < gas.length; i++) {
        int diff = gas[i] - cost[i];
        total += diff; tank += diff;
        if (tank < 0) { start = i + 1; tank = 0; }   // restart after the failure point
    }
    return total < 0 ? -1 : start;
}

Time O(n) · Space O(1). Insight: the key lemma — if the tank goes negative at i, no index between the old start and i can be the answer, so you skip them all in one pass. Proving that lemma is the entire interview, not the code.
