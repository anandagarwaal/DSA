More DP Problems

Four reps across the families: subset-sum, longest increasing subsequence, edit distance, and a state-machine.

From Lesson 0031 you have the five-question procedure and the linear / knapsack / two-sequence shapes. These reps hit the families that trip people up: 0/1 knapsack, LIS (and its O(n log n) twist), edit distance, and a state-machine. Run the five questions on each before peeking — keep the framework reference open.

Drill 1 — 0/1 knapsack LeetCode 416 · Partition Equal Subset Sum

Can the array be split into two subsets of equal sum?

Hint

If total is odd, no. Else target = sum/2; ask "can some subset hit target?" — a 0/1 knapsack. dp[s] = is sum s reachable. Iterate sums downward so each item is used once.

Solution (Java) 
public boolean canPartition(int[] nums) {
    int sum = 0; for (int x : nums) sum += x;
    if (sum % 2 != 0) return false;
    int target = sum / 2;
    boolean[] dp = new boolean[target + 1];
    dp[0] = true;
    for (int x : nums)
        for (int s = target; s >= x; s--)     // DOWNWARD = each item used once
            dp[s] = dp[s] || dp[s - x];
    return dp[target];
}

Time O(n·target) · Space O(target). Insight: the reverse inner loop is the whole 0/1-vs-unbounded distinction — descending sums stop an item being reused in the same pass. Forward would be unbounded knapsack.

Drill 2 — subsequence DP LeetCode 300 · Longest Increasing Subsequence

Length of the longest strictly increasing subsequence.

Hint

O(n²): dp[i] = LIS ending at i; dp[i] = 1 + max(dp[j]) over j<i, a[j]<a[i]. The O(n log k) twist: keep a "tails" array, binary-search the insertion point for each value.

Solution (Java) 
// O(n log n): tails[k] = smallest possible tail of an increasing subseq of length k+1.
public int lengthOfLIS(int[] nums) {
    int[] tails = new int[nums.length]; int size = 0;
    for (int x : nums) {
        int lo = 0, hi = size;                // binary search for x's slot
        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;
            if (tails[mid] < x) lo = mid + 1; else hi = mid;
        }
        tails[lo] = x;                        // extend or overwrite
        if (lo == size) size++;
    }
    return size;
}

Time O(n log n) · Space O(n). Insight: this fuses DP with binary search — each value replaces the smallest tail ≥ it, keeping tails sorted. Knowing both the O(n²) DP and this O(n log n) refinement is a strong Staff signal.

Drill 3 — two-string grid LeetCode 72 · Edit Distance

Minimum insert/delete/replace operations to turn string A into string B.

Hint

dp[i][j] = edits for prefixes. Match → carry dp[i-1][j-1]; else 1 + min(replace dp[i-1][j-1], delete dp[i-1][j], insert dp[i][j-1]). Base rows/cols = "delete/insert everything."

Solution (Java) 
public int minDistance(String a, String b) {
    int m = a.length(), n = b.length();
    int[][] dp = new int[m + 1][n + 1];
    for (int i = 0; i <= m; i++) dp[i][0] = i;     // delete all of a's prefix
    for (int j = 0; j <= n; j++) dp[0][j] = j;     // insert all of b's prefix
    for (int i = 1; i <= m; i++)
        for (int j = 1; j <= n; j++)
            dp[i][j] = (a.charAt(i-1) == b.charAt(j-1))
                ? dp[i-1][j-1]
                : 1 + Math.min(dp[i-1][j-1],          // replace
                      Math.min(dp[i-1][j], dp[i][j-1])); // delete, insert
    return dp[m][n];
}

Time O(m·n) · Space O(m·n). Insight: the three predecessors map exactly to the three edit operations — naming which cell is which operation is how you explain (and debug) the recurrence under pressure.

Drill 4 — state-machine DP LeetCode 309 · Best Time to Buy/Sell with Cooldown

Maximise profit with unlimited transactions, but a one-day cooldown after each sell.

Hint

Three states per day: hold (own a share), sold (just sold today), rest (idle, free to buy). Transition between them day by day.

Solution (Java) 
public int maxProfit(int[] prices) {
    int hold = Integer.MIN_VALUE, sold = 0, rest = 0;
    for (int p : prices) {
        int prevSold = sold;
        sold = hold + p;                      // sell today (was holding)
        hold = Math.max(hold, rest - p);      // keep holding, or buy from rest
        rest = Math.max(rest, prevSold);      // stay idle, or cooldown after a sale
    }
    return Math.max(sold, rest);              // never end while still holding
}

Time O(n) · Space O(1). Insight: modelling the problem as transitions between named states is the unlock — once the three states and their legal moves are written down, the code is a direct transcription. The whole stock-problem family is this pattern with different states.

Self-check

Classify each: 0/1 knapsack reverse-loop (D1), LIS with binary-search tails (D2), edit-distance grid (D3), state-machine transitions (D4). The two highest-value takeaways: the downward-vs-upward inner loop (0/1 vs unbounded), and "model it as states then transcribe" for any stock/transaction problem.
