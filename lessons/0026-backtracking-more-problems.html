Lesson 0026 · Backtracking — Reps

More Backtracking Problems

Four reps: combination-sum with reuse, duplicate-skipping, string partitioning, and the N-Queens board.

From Lesson 0025 you have choose / explore / un-choose and the subset-vs-permutation fork. These reps add the two hardest sub-skills: pruning (cut branches that can't succeed) and duplicate handling (sort, then skip equal siblings). State the state-space tree before coding.

Drill 1 — reuse allowed LeetCode 39 · Combination Sum

Find all combinations summing to a target; each number may be reused unlimited times.

Hint

Recurse with a start index, but pass i (not i+1) so the same number can repeat. Prune when the remaining target goes negative.

Solution (Java) 
public List<List<Integer>> combinationSum(int[] cand, int target) {
    List<List<Integer>> res = new ArrayList<>();
    backtrack(cand, target, 0, new ArrayList<>(), res);
    return res;
}
private void backtrack(int[] cand, int rem, int start,
                       List<Integer> path, List<List<Integer>> res) {
    if (rem == 0) { res.add(new ArrayList<>(path)); return; }
    if (rem < 0) return;                          // prune: overshot
    for (int i = start; i < cand.length; i++) {
        path.add(cand[i]);
        backtrack(cand, rem - cand[i], i, path, res);  // i, not i+1 → reuse
        path.remove(path.size() - 1);
    }
}

Time O(2^target) worst case · Space O(target/min). Insight: passing i keeps the current element in play (reuse) while start still blocks earlier ones, so each multiset is counted once.

Drill 2 — skip duplicates LeetCode 90 · Subsets II

All subsets of an array that may contain duplicates — no duplicate subsets in output.

Hint

Sort first. Within one recursion level, skip an element equal to the previous one (i > start && nums[i] == nums[i-1]) — that collapses sibling branches that would produce identical subsets.

Solution (Java) 
public List<List<Integer>> subsetsWithDup(int[] nums) {
    Arrays.sort(nums);                           // bring duplicates together
    List<List<Integer>> res = new ArrayList<>();
    backtrack(nums, 0, new ArrayList<>(), res);
    return res;
}
private void backtrack(int[] nums, int start, List<Integer> path,
                       List<List<Integer>> res) {
    res.add(new ArrayList<>(path));
    for (int i = start; i < nums.length; i++) {
        if (i > start && nums[i] == nums[i - 1]) continue;  // skip dup sibling
        path.add(nums[i]);
        backtrack(nums, i + 1, path, res);
        path.remove(path.size() - 1);
    }
}

Time O(n·2ⁿ) · Space O(n). Insight: i > start (not i > 0) is critical — it skips duplicates only among siblings, still allowing a value to repeat deeper down a single path. This sort-then-skip idiom recurs everywhere duplicates appear.

Drill 3 — partition with a validity test LeetCode 131 · Palindrome Partitioning

Partition a string so every substring is a palindrome; return all such partitions.

Hint

The choice at each step is "where to cut next." Try every prefix; if it's a palindrome, recurse on the rest. The cut position is the start index for the next level.

Solution (Java) 
public List<List<String>> partition(String s) {
    List<List<String>> res = new ArrayList<>();
    backtrack(s, 0, new ArrayList<>(), res);
    return res;
}
private void backtrack(String s, int start, List<String> path,
                       List<List<String>> res) {
    if (start == s.length()) { res.add(new ArrayList<>(path)); return; }
    for (int end = start + 1; end <= s.length(); end++) {
        if (isPal(s, start, end - 1)) {          // only valid cuts recurse
            path.add(s.substring(start, end));
            backtrack(s, end, path, res);
            path.remove(path.size() - 1);
        }
    }
}
private boolean isPal(String s, int i, int j) {
    while (i < j) if (s.charAt(i++) != s.charAt(j--)) return false;
    return true;
}

Time O(n·2ⁿ) · Space O(n). Insight: the palindrome test is the prune — invalid prefixes never recurse, so the branching factor collapses well below the naive 2ⁿ cuts.

Drill 4 — constraints on a board LeetCode 51 · N-Queens

Place N queens on an N×N board so none attack each other; return all configurations.

Hint

Place one queen per row. Track attacked columns and both diagonals in sets (col, r-c, r+c). Recurse row by row; the sets make each validity check O(1).

Solution (Java) 
private List<List<String>> res = new ArrayList<>();
private Set<Integer> cols = new HashSet<>(), diag = new HashSet<>(), anti = new HashSet<>();
public List<List<String>> solveNQueens(int n) {
    place(0, n, new int[n]);
    return res;
}
private void place(int r, int n, int[] queenCol) {
    if (r == n) { res.add(render(queenCol, n)); return; }
    for (int c = 0; c < n; c++) {
        if (cols.contains(c) || diag.contains(r - c) || anti.contains(r + c)) continue;
        cols.add(c); diag.add(r - c); anti.add(r + c); queenCol[r] = c;     // choose
        place(r + 1, n, queenCol);                                          // explore
        cols.remove(c); diag.remove(r - c); anti.remove(r + c);             // un-choose
    }
}

Time O(n!) · Space O(n). Insight: encoding the two diagonals as r-c and r+c turns attack-checking into O(1) set lookups — the trick that makes N-Queens a clean backtracking problem rather than a messy one.

Self-check

Classify each: reuse via start-stays-at-i (D1), sort-then-skip-siblings for duplicates (D2), validity-pruned partition (D3), constraint-set board placement (D4). The duplicate-skip (i > start) and the diagonal encoding are the two most interview-tested tricks here.
