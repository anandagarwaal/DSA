Lesson 0022 · Heaps & Top-K

Heaps & Top-K Patterns

When you need the best k of n — not all of them sorted — a heap of size k beats a full sort.

A heap (Java's PriorityQueue) gives O(log n) insert and O(1) peek of the min (or max). The killer insight for interviews: to find the k largest, keep a min-heap of size k — evict the smallest whenever it overflows. That's O(n log k), beating an O(n log n) full sort when k ≪ n, and it streams.

The counter-intuitive bit: for k largest you use a min-heap (so the smallest of your current top-k is cheap to evict), and for k smallest a max-heap. Saying that out loud — and why — separates people who memorised from people who understand. The heap holds your "current best k"; its root is the weakest survivor.

The size-k heap template

// k largest elements, O(n log k), O(k) space.
PriorityQueue<Integer> minHeap = new PriorityQueue<>();   // natural order = min-heap
for (int x : nums) {
    minHeap.offer(x);
    if (minHeap.size() > k) minHeap.poll();   // drop the smallest survivor
}
// minHeap now holds the k largest; minHeap.peek() is the kth largest.

For custom order: new PriorityQueue<>((a,b) -> a.freq - b.freq). For a max-heap of ints: new PriorityQueue<>(Collections.reverseOrder()).

Pattern signals. "k largest/smallest/closest/most frequent", "merge k sorted …", "median of a stream", "schedule by priority", "repeatedly take the best/worst remaining". If you only need the top k (not a full ordering), reach for a heap.

Check your model first

Drill — three problems

Drill 1 — top-k with counts LeetCode 347 · Top K Frequent Elements

Return the k most frequent elements.

Hint

Count with a hashmap, then keep a size-k min-heap ordered by frequency. (Bucket sort by frequency gives an O(n) alternative — mention it.)

Solution (Java) 
public int[] topKFrequent(int[] nums, int k) {
    Map<Integer,Integer> freq = new HashMap<>();
    for (int x : nums) freq.merge(x, 1, Integer::sum);
    PriorityQueue<Integer> heap =
        new PriorityQueue<>((a, b) -> freq.get(a) - freq.get(b));  // min by freq
    for (int key : freq.keySet()) {
        heap.offer(key);
        if (heap.size() > k) heap.poll();
    }
    int[] res = new int[k];
    for (int i = 0; i < k; i++) res[i] = heap.poll();
    return res;
}

Time O(n log k) · Space O(n). Insight: heap-of-k beats sorting all distinct elements; if asked for strict O(n), pivot to bucket sort by frequency.

Drill 2 — merge k lists with a heap LeetCode 23 · Merge k Sorted Lists

Merge k sorted linked lists into one. A frequent hard.

Hint

Min-heap of the current head of each list. Poll the smallest, append it, push its next. The heap always holds ≤ k nodes.

Solution (Java) 
public ListNode mergeKLists(ListNode[] lists) {
    PriorityQueue<ListNode> pq = new PriorityQueue<>((a, b) -> a.val - b.val);
    for (ListNode l : lists) if (l != null) pq.offer(l);
    ListNode dummy = new ListNode(0), tail = dummy;
    while (!pq.isEmpty()) {
        ListNode n = pq.poll();
        tail.next = n; tail = n;
        if (n.next != null) pq.offer(n.next);
    }
    return dummy.next;
}

Time O(N log k) for N total nodes · Space O(k). Insight: the heap size stays k, not N — that's why it beats repeatedly scanning all k heads (O(Nk)).

Drill 3 — two heaps LeetCode 295 · Find Median from Data Stream

Support addNum and findMedian over a growing stream.

Hint

A max-heap for the lower half, a min-heap for the upper half. Keep sizes balanced (differ by ≤ 1). Median is the larger heap's root, or the average of both roots when equal.

Solution (Java) 
private PriorityQueue<Integer> lo = new PriorityQueue<>(Collections.reverseOrder()); // max-heap
private PriorityQueue<Integer> hi = new PriorityQueue<>();                            // min-heap
public void addNum(int num) {
    lo.offer(num);
    hi.offer(lo.poll());              // funnel through to keep order across heaps
    if (hi.size() > lo.size()) lo.offer(hi.poll());   // rebalance
}
public double findMedian() {
    return lo.size() > hi.size() ? lo.peek() : (lo.peek() + hi.peek()) / 2.0;
}

Time O(log n) add · O(1) median · Space O(n). Insight: the "push to one, pop to the other" funnel guarantees every element in lo ≤ every element in hi — that invariant is what makes the roots the median.
