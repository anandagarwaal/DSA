Lesson 0012 · Interleaving

Mixed Retrieval — Binary Search + Windows + Pointers + Hashing

Four tools now. The trap: missing a hidden monotonic predicate and brute-forcing instead.

Do this after a 2–3 day gap from Lessons 0010–0011. The new failure mode is not seeing the "minimise/maximise the value such that feasible" shape and reaching for a linear scan when an O(log) bisection exists. Train the recognition.

The decision fork to internalise

SignalReach for
"Min/max value such that a feasibility check passes"Binary search on the answer
Sorted array, find element / boundaryBinary search (lower/upper bound)
Longest/shortest contiguous run, positive constraintSliding window
Sorted, pair/triplet, O(1) spaceConverging two pointers
Contiguous sum with negativesPrefix sum + hash map
"Seen it?" / counts / group-byHash set / map

Drill — name the tool, cold

State the approach and its complexity in under 30 seconds, then check.

Debrief

The Staff-level reflex: when you hear "smallest/largest X such that Y is achievable," ask "is feasibility monotonic in X?" If yes, you have an O(log·check) solution before writing a line. Contrast that with windows (contiguous + monotonic aggregate) and sorting+pointers (pair search). Naming the discriminator is what interviewers score.
