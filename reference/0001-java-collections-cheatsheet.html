HashMap idioms

Map<Integer,Integer> m = new HashMap<>();

// count frequencies
m.merge(x, 1, Integer::sum);            // m[x] += 1, defaulting to 0
m.put(x, m.getOrDefault(x, 0) + 1);     // equivalent, classic form

// accumulate into a list (group-by)
Map<String,List<String>> g = new HashMap<>();
g.computeIfAbsent(key, k -> new ArrayList<>()).add(val);

// iterate entries
for (Map.Entry<Integer,Integer> e : m.entrySet()) {
    int k = e.getKey(), v = e.getValue();
}

ArrayDeque as stack & queue

Deque<Integer> st = new ArrayDeque<>();
st.push(1); st.push(2);      // stack: LIFO
int top = st.pop();          // 2

Deque<Integer> q = new ArrayDeque<>();
q.offer(1); q.offer(2);      // queue: FIFO
int front = q.poll();        // 1

Prefer ArrayDeque over Stack (legacy, synchronized) and over LinkedList (slower, more memory).

Gotchas that cost interview points

  • == vs .equals(): for Integer/String always use .equals(). == compares references (and Integer caches only −128..127).
  • Comparator overflow: (a,b)->a-b overflows for large ints. Use Integer.compare(a,b).
  • Modifying a collection while iterating throws ConcurrentModificationException. Collect changes, apply after — or use an iterator's remove().
  • Autoboxing in hot loops: prefer primitive arrays (int[]) over List<Integer> when performance matters.
