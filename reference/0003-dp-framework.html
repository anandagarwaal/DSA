Dynamic Programming — A Reusable Framework

A fixed five-question procedure that turns any DP problem into mechanical code, plus the canonical templates.

DP applies when a problem has optimal substructure (the answer is built from answers to subproblems) and overlapping subproblems (the same subproblem recurs). Don't pattern-match on memorised solutions — run the procedure. Source: cp-algorithms — DP.

The five questions

#QuestionExample (House Robber)
1State: what defines a subproblem?dp[i] = max loot from houses 0..i
2Choice: what decisions at each state?Rob house i, or skip it
3Recurrence: combine sub-answersdp[i] = max(dp[i-1], dp[i-2] + a[i])
4Base case: smallest subproblemsdp[0]=a[0], dp[1]=max(a[0],a[1])
5Order / answer: fill direction & where the result sitsLeft→right; answer at dp[n-1]

Write the recurrence first in plain words, then translate. The recurrence is the problem — everything else (memo vs table, space optimisation) is mechanical.

Top-down (memoization) template

Integer[] memo;                              // null = uncomputed
int solve(int i) {
    if (isBase(i)) return baseValue;
    if (memo[i] != null) return memo[i];     // overlap → reuse
    int best = combine(solve(subproblemA), solve(subproblemB));
    return memo[i] = best;
}

Write the recursion naturally, then add the memo array. Easiest to derive; recursion depth is the only risk. Great when the state space is sparse or irregular.

Bottom-up (tabulation) template

int[] dp = new int[n + 1];
dp[base] = baseValue;
for (int i = lo; i <= hi; i++)               // an order where deps are already done
    dp[i] = combine(dp[i - 1], dp[i - 2] /* ... */);
return dp[n];

No recursion overhead; the fill order must respect dependencies. Often the same recurrence as the memo version, just iterative.

Space optimisation

// If dp[i] depends only on dp[i-1] and dp[i-2], keep two scalars:
int prev2 = base0, prev1 = base1;
for (int i = 2; i <= n; i++) {
    int cur = combine(prev1, prev2);
    prev2 = prev1; prev1 = cur;
}
return prev1;

When each row depends only on the last one or two, drop the array to O(1) (1-D) or roll a 2-D table down to one row. Mentioning this rolling-array trick is a frequent interview bonus.

1-D vs 2-D recurrence shapes

// Coin Change — fewest coins to make 'amount' (unbounded knapsack, 1-D):
int[] dp = new int[amount + 1];
Arrays.fill(dp, amount + 1); dp[0] = 0;
for (int a = 1; a <= amount; a++)
    for (int c : coins) if (c <= a) dp[a] = Math.min(dp[a], dp[a - c] + 1);
return dp[amount] > amount ? -1 : dp[amount];

// Edit Distance — two strings, 2-D grid:
int[][] dp = new int[m + 1][n + 1];
for (int i = 0; i <= m; i++) dp[i][0] = i;    // delete all
for (int j = 0; j <= n; j++) dp[0][j] = j;    // insert all
for (int i = 1; i <= m; i++)
    for (int j = 1; j <= n; j++)
        dp[i][j] = (a.charAt(i-1) == b.charAt(j-1))
            ? dp[i-1][j-1]
            : 1 + Math.min(dp[i-1][j-1], Math.min(dp[i-1][j], dp[i][j-1]));
return dp[m][n];

How to use this in an interview

Say the five answers out loud before coding: "State is …, the choice is …, so the recurrence is …, base case …, and I'll fill … returning …." This narration is exactly the "why correct / why optimal" signal Google and Meta probe for. Then code the memo version (safest to get right), and mention the bottom-up + space-optimised refinements as follow-ups.
